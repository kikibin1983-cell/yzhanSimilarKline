# 从玩到学：五个小练习

先运行游戏、造一间小屋并导出备份。学习时一次只改一个功能，保留能运行的版本。

## 代码地图

| 文件 | 看什么 |
| --- | --- |
| `src/blocks.js` | 方块 ID、名称、纹理、碰撞属性 |
| `src/generation.js` | 种子哈希、平滑噪声、山地、洞穴、矿石、跨区块树木 |
| `src/world.js` | 16 格区块、负坐标转换、建筑修改覆盖、缓存淘汰 |
| `src/meshing.js` | 隐藏内部面，将可见方块表面转换为三角形 |
| `src/renderer.js` | 本地像素纹理、Three.js 场景、灯光、雾和资源释放 |
| `src/player.js` | 重力、跳跃、逐轴碰撞、飞行与安全出生 |
| `src/interaction.js` | 体素射线，找到准星命中格和相邻放置格 |
| `src/storage.js` | 存档验证、IndexedDB 事务、按顺序写入 |
| `src/main.js` | 输入、固定步长模拟、模式切换与模块连接 |
| `src/ui.js` / `index.html` / `style.css` | 快捷栏、菜单和外观 |
| `server.mjs` | 本地文件服务、路径允许列表和端口识别 |

世界生成和建筑修改是两层：种子负责原始世界，`world.edits` 只记录改动。空气也是有效改动，不存它就会让挖掉的石头在重启后回来。

## 1. 添加一种建造方块

入口：`src/blocks.js` 的 `BLOCKS` 数组。

先在数组末尾添加新条目，用现有纹理测试，例如名称“青石”、`solid: true`、`tile: 3`。把新 ID 添加到 `BUILDABLE`，再打开 E 菜单。

不要插入到数组中间或重新编号：ID 会进入存档。验证：放置新方块、碰撞、导出、刷新恢复、运行 `npm.cmd test`。旧版本读取新 ID 会拒绝导入，因此保留旧备份；真正发布时应设计存档版本升级。

## 2. 让山地更高

入口：`src/generation.js` 的 `surfaceHeight`。

噪声的 scale 决定起伏范围，系数决定高差。小幅调整 `23` 的系数，保持最高地形与树木在 96 格高度之内。创建一个**新种子世界**观察效果。

修改生成算法会改变未编辑地形；正式发布时必须递增 `GENERATOR_VERSION` 并说明迁移策略。不要用已有重要存档直接测试新算法。验证同种子生成一致以及树木边界，运行世界测试。

## 3. 调整移动速度

入口：`src/player.js` 的 `update`，步行速度为 4.6，冲刺为 7，飞行为 8/17。

先将步行速度调到 5.2，保持归一化方向逻辑和碰撞子步。验证直行、斜行、墙角、跳跃和飞行，运行 `node --test tests/physics.test.mjs`。

原理：画面每秒绘制多少帧会变化，模拟以 1/60 秒的固定步长推进，避免高低帧率下移动速度不同。

## 4. 生成一个小平台

入口：`src/generation.js`。先理解 `getBlock` 与 `generateChunk` 的一致性测试。

在固定位置设计一个 5×5 石头平台，要求它的方块判断是坐标的确定性函数。把同一个规则应用到直接查询和区块生成路径；不使用 `Math.random()` 或依赖先加载哪个区块。

验证：以不同顺序加载相邻区块，平台形状相同；平台跨越 x=15/16 时无缺口。扩展 `tests/world.test.mjs` 的手工坐标用例。

## 5. 改快捷栏显示

入口：`src/ui.js` 的 `hotbar` 和 `style.css` 的 `.slot`。

给选中槽位增加更明显的边框，或显示方块名。显示文字用 `textContent`，避免把种子等用户文字当 HTML 插入。

验证：1–9、滚轮和 E 选择都刷新正确槽位；菜单不遮挡准星；1280×720 和较窄窗口均能看清。外观调整通常只需实际视觉检查。

## 如何排查问题

按 F12 查看浏览器控制台；F3 查看帧率、坐标和区块队列。先复现，记下坐标与种子，再编写能触发错误的测试。处理存档时先导出备份，不直接删除浏览器数据来掩盖故障。

逐步学习的建议顺序：方块和坐标 → 世界生成 → 网格与光照 → 角色碰撞 → 存档 → 库存/合成。扩展生存和多人时再讨论独立系统及存档兼容，不需要先加复杂框架。
