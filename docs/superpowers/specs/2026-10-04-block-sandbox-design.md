# 方块沙盒：首版设计

日期：2026-10-04  
状态：待用户审阅；尚未进入实现阶段

## 1. 用途与已确认范围

用户主要希望自己玩，之后通过源码学习游戏开发。用户已确认采用浏览器版，首版包含第一人称探索、创造模式建造、种子地形、区块加载、中文界面、存档与导出备份。

成功标准是：在 Windows 本机启动后，可以进入一个三维方块世界，持续探索、挖掘、建造，关闭后能恢复世界和玩家位置；源码结构能让初学者找到并修改对应功能。

《我的世界》是操作和玩法参考。首版是独立实现的方块沙盒，不宣称与原作功能完整一致或存档兼容。使用自行生成的像素纹理和独立名称，交付源码、启动入口、操作说明、开发学习指南及验证记录。

## 2. 工程位置与运行方式

- 游戏项目放在 `games/block-sandbox/`，与现有股票应用分开。
- 不改股票应用入口、Python 环境、依赖、端口或用户数据。
- 使用 JavaScript ES modules 和 Three.js；原生 HTML/CSS 编写菜单，避免引入前端框架。
- Three.js 使用固定版本、锁文件和项目内本地资源，运行时不依赖 CDN。
- `启动游戏.bat` 检查 Node.js，然后启动只监听 `127.0.0.1` 的静态资源服务，默认端口 8765。端口占用时验证是本游戏再打开，否则明确提示。
- 初次开发准备依赖需要下载；交付时包含运行需要的本地资源。此后启动游戏不需要联网。
- 启动器与服务独立于 Streamlit；不安装系统级服务或修改防火墙。
- 支持当前桌面 Chromium 浏览器，要求 WebGL2。缺少图形支持时显示中文说明。

## 3. 首版世界与内容边界

以下规模是待审阅的工程设计值，实际性能由本机验证决定：

- 一个有限世界：水平范围 `-256 <= x,z < 256`，垂直范围 `0 <= y < 96`。
- 世界以 16×16 的水平区块组织，每区块有固定高度。世界边缘通过碰撞边界和雾处理，越界方块不可编辑。
- 相同种子、相同生成器版本、相同坐标产生相同地形，不依赖区块生成顺序。
- 生成草地、起伏山地、沙岸、树林、水面、基础洞穴和少量矿石。
- 基础方块包括草、泥土、石头、沙子、木头、树叶、木板、砖、玻璃、煤矿、铁矿和水；空气单独作为空单元。
- 基岩位于底部且不可破坏。水为固定体素，不模拟流体扩散；水中降低移动速度，按跳跃键可上浮。
- 树木生成跨区块时保持一致，不因生成次序改变或截断。
- 初次出生选择具有站立空间的干燥地面，避免水中、洞内和树干内部。
- 方块素材由项目生成，采用像素纹理、草地与石头等明确配色。第一人称建造工具呈现保持简洁。

首版只有创造模式：方块数量无限，玩家不受伤。生存、合成、怪物、红石、多人、流体模拟及无限世界属于后续独立阶段，不能作为首版已完成能力。

## 4. 操作与体验

- WASD 移动，鼠标控制视角，空格跳跃，Shift 冲刺。
- F 切换飞行；飞行时空格上升、Ctrl 下降；飞行也遵守实体和世界边界碰撞。
- 左键挖掘、右键放置；点击和持续按住均可操作，持续动作有节流。
- 可交互距离为 6 格，瞄准方块显示轮廓。不可隔着实体方块编辑远处方块。
- 放置目标必须为空气，不能覆盖玩家身体；默认不允许替换水。水方块由世界生成，不在首版建造选择中。
- 1–9 或滚轮切换快捷栏；E 打开方块选择，可将选定方块放入当前快捷栏槽位。
- Esc 解除鼠标锁定并暂停游戏模拟；点击继续重新请求鼠标锁定。第一次点击进入游戏只获取锁定，不立即挖掘。
- 自定义像素风中文首页包括继续游戏、新建世界、操作帮助和设置。
- 游戏画面包括准星、九格快捷栏、选中方块名称；坐标和帧率只在可切换的信息面板中显示。
- 设置提供视距、鼠标灵敏度、音量和画质。视距有低/中/高三档，分别为 2/3/4 个区块半径，默认中档；像素比有上限。
- 轻量程序化交互音效在用户手势后启用，可静音。
- 新建世界允许输入种子；已有世界存在时，新建操作需明确确认后才替换当前存档。
- 首版提供一个当前世界存档。用户可用导出文件保留多个世界，导入替换当前世界前显示确认。

## 5. 模块与数据流

建议模块边界如下，最终文件可按实现复杂度合理拆分：

| 模块 | 职责 | 接口与依赖 |
| --- | --- | --- |
| `blocks` | 方块 ID、名称、固体/透明属性、纹理索引 | 不依赖界面或 Three.js |
| `generation` | 种子哈希、地形、洞穴、树木 | 纯确定性函数；读取方块定义 |
| `world` | 坐标转换、区块数据、编辑覆盖、加载与卸载 | `getBlock`、`setBlock`；生成器与保存的修改 |
| `meshing` | 输出可见表面的顶点、法线、纹理坐标 | 读取区块及邻格；纯数据输出 |
| `renderer` | Three.js 场景、纹理、区块网格、雾、灯光、轮廓 | 消费网格；负责 GPU 资源生命周期 |
| `player` | 输入、固定步长移动、重力、碰撞、飞行 | 读取世界碰撞；输出位置与视角 |
| `interaction` | 体素射线、挖掘、放置、操作节流 | 读取世界和玩家；通过世界接口修改 |
| `storage` | IndexedDB、校验、导入导出、版本 | 不依赖 Three.js；存取明确的数据结构 |
| `ui` | 菜单、暂停、快捷栏、设置、存档状态 | 调用游戏命令，接收状态 |
| `main` | 启动、主循环、模块连接和模式切换 | 不承载地形或存档细节 |

启动路径：检查渲染支持 → 加载配置及存档 → 创建世界 → 加载出生点附近区块 → 创建玩家 → 显示进入按钮 → 获取鼠标锁定 → 模拟与渲染。

编辑路径：体素射线命中 → 距离/边界/基岩/玩家相交校验 → 写修改覆盖 → 标记自身及相邻区块的网格脏状态 → 进入存档队列。

区块生成优先处理玩家附近，按帧预算分摊工作，避免一次性生成完整世界。只生成可见表面网格，不为每个方块创建 Three.js 对象。区块卸载释放 GPU 网格并移除基础体素数据，用户修改覆盖仍由独立数据层保留。

## 6. 移动、碰撞和渲染可靠性

- 玩家使用轴对齐碰撞盒，高约 1.8 格、宽约 0.6 格；摄像机位于眼高。
- 固定模拟步长与渲染帧率解耦，限制单帧补步数量；失去焦点后暂停，防止切回页面后大步穿墙。
- 逐轴处理实体碰撞，限制每次位移或使用子步，验证快速移动、飞行和区块边界不穿透。
- 尚未准备的区块不能作为空气通过；优先生成玩家碰撞邻域，必要时暂缓移动。
- 从飞行切换到步行时重新执行重力与落地判断。存档位置被编辑堵住时移至最近安全位置，并提示原因。
- 实心、透明和水表面分开处理；空气之间不生成表面，区块接缝不应出现缺面。
- 使用体素网格遍历进行交互射线，返回命中格与相邻放置格，避免对整个世界逐方块查询。
- 渲染距离内才保留区块网格，卸载时释放几何体；共用纹理和材质由渲染器统一管理。

## 7. 存档与恢复

- IndexedDB 保存 `formatVersion`、`generatorVersion`、种子、玩家位置/视角/模式、快捷栏、设置和修改覆盖。
- 不保存完整生成地形。修改为空气也必须保存，否则挖掉的方块会重生；恢复为生成器原值时可移除覆盖项。
- 每次成功保存使用事务写入一致快照。单一保存队列避免旧快照晚写覆盖新快照；按修改序号跟踪已保存状态。
- 编辑、位置移动和界面设置变化触发保存，常规自动保存间隔不超过 5 秒。暂停菜单提供立即保存，并显示保存中、已保存或失败。
- 页面隐藏时尝试保存，但不依赖浏览器退出回调保证落盘。说明书提示关闭前等待已保存状态。
- 同一来源下继续游戏恢复存档；浏览器清理站点数据、隐私模式或换浏览器可能失去本地存档，导出备份是可移植恢复方式。
- JSON 导出包含必要元数据与修改覆盖。导入限制文件大小（首版上限 20 MiB）、坐标、方块 ID、种子长度、结构和版本；不支持的版本拒绝导入。
- 导入校验完全通过并确认后，才通过事务替换存档；错误导入保留当前世界。
- 存储不可用或配额不足时继续允许游玩，明确显示无法持久保存，并提供导出当前内存世界。
- 首版存档仅支持本项目，不解析 Minecraft 地图。

## 8. 异常处理

资源缺失、WebGL 初始化失败、存档读取失败和启动端口冲突均显示可操作的中文信息。损坏存档不能被启动时自动覆盖；用户可主动导出可读取的数据或确认重建。

图形上下文丢失时暂停模拟并提示刷新，不能宣称未落盘的编辑已经保存。主循环异常停止并显示错误信息，不反复产生错误或继续破坏存档。

## 9. 验证与首版验收

### 自动验证

使用 Node 内置测试运行器覆盖真实风险：

1. 同种子地形一致、不同生成顺序一致、树木跨区块一致。
2. 正负坐标映射、世界边界、相邻区块编辑与网格接缝。
3. 可见面生成、透明相邻关系、空区块网格。
4. 体素射线的方向、距离、边界和放置法线。
5. 玩家落地、墙面、顶面、快速移动、飞行和未加载区块碰撞。
6. 挖掘为空气的覆盖、恢复原始方块、序列化往返、错误版本和导入校验。
7. 保存队列的先后顺序与写入失败恢复。

### 实际浏览器验证

- 从启动入口进入游戏，确认本地资源加载成功且无外部资源请求。
- 实际查看中文首页、世界画面、快捷栏、暂停和设置；保留截图。
- 检查获取/解除鼠标锁定、移动跳跃、飞行、挖掘、放置和方块选择。
- 在区块边界挖掘和放置，确认碰撞与画面同步。
- 建造后保存、刷新、关闭页面再打开，确认方块、位置和快捷栏恢复。
- 导出、修改世界、再导入，确认恢复；错误文件不能替换原世界。
- 检查运行时离线可玩，以及存档失败时的提示和内存导出路径。
- 记录本机浏览器、窗口尺寸、画质、帧率和区块数量。目标在 1280×720 中档达到可玩水平，期望稳定约 30 FPS 或以上；这是目标，不是未测量的承诺。达不到时降低视距或优化，并记录实际结果。
- 连续探索观察已加载区块、网格数量是否受视距约束，防止随探索距离无限累积。

浏览器自动化不能可靠覆盖真实鼠标锁定时，明确记录人工验收项，不能用纯逻辑测试替代实际操作完成声明。

## 10. 学习资料和后续阶段

`README.md` 说明启动、操作、存档备份与首版限制；`LEARNING.md` 提供模块地图和五个练习：添加方块、调整山地、修改移动速度、添加简单建筑生成、扩展快捷栏显示。每个练习给出文件位置、参数意义、验证方法。
